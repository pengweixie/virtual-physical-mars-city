## 账 ① · 床位与工位普查(先算,别的账都吃它)

**问题:** 这座城能住多少人、要多少人。逐张卡数床位与常驻人数;卡上没数的写缺口,不估。

**方法:** 脚本遍历 80 张卡(+1 无卡模块记为缺口),对每张卡的 `label/detail/specs/sim/physics` 全文找「床/床位/bunk/bed/sleep」与「常驻/工位/crew/staff/人员/operator/人」附近的数字,**候选行打印出来由人逐条核对上下文**(正则会把「床身」「实验台」「病床」都抓进来,机器只找不判);核过的行进 JSON,每行带卡路径 + POI id + 字段名 + 卡提交号。分四列:**床位(睡)** / **常驻人数(卡明说)** / **工位(卡明说的操作位数,不等于人)** / **缺口(卡无数)**。总和由脚本求,不手记。

**预期区间(数据前):**

- E1.2 卡上**明说常驻人数**的资产 **≤ 25 个**(≤ 30% 的 82);其余是缺口。这是本账的头条方向:**「城里没有人这一层」在卡上表现为大多数单位不知道自己要几个人**。

## 账 ③ · 配额账(三条线并印,不合并)

**问题:** 三条互不兼容的限值下,每个已裁定位置的配额多久耗尽。

**方法:** 三条线:(a)城用 **20 mSv/yr 舱内**(城规,引 plaza 卡 / 派发词);(b)村子自设 **50 mSv/火星年**(plaza 卡,`9a75308`);(c)职业生涯 **NASA-STD-3001 Vol.1 Rev.C 600 mSv 终身** + **ICRP 103 20 mSv/yr 五年均、任一年 ≤ 50**。每条线独立算「耗尽 sol 数」,**三列并排,不取交集不取最严**——因为它们回答的问题不同(城规是设计口径、村规是自设总额、职业限是人一辈子)。

**预期区间:**
- E3.1 独立重写村子的公式,X = 0/0.5/1 h EVA 下床位 std 到 20 mSv 必须复现 **263 / 228 / 201 sol**(±1 sol 取整差);occupancy v1 加权 **0.1250 / 0.1354 / 0.1457 mSv/sol → 160 / 148 / 137 sol**。这是跨实现复核闸(闸门说谎第 10 种的反面),不复现就停。
- E3.2 职业生涯 600 mSv 在 occupancy v1(X = 0.5)下 **4,300–4,600 sol ≈ 6.4–6.9 火星年 ≈ 12–13 地球年**;地表常住(234 mSv/yr)**2.4–2.7 地球年**。
- E3.3 ICRP 五年均 20 mSv/yr 对村子床位地板 27:**任何作息组合都越线**(27 > 20 且加 EVA 只增)——结论是「ICRP 职业线在村子里不可满足,不是靠排班能救的」。不对称:能证明越线;不能证明地下城满足(地板未闭合)。
- E3.4 三条线的**排序不固定**:对短住(< 1 火星年)最紧的是城用 20;对长住(> 5 年)最紧的是终身 600。本账要打印交叉点(sol 数)。

**闸门:** G3.1 E3.1 复现;G3.2 极限:地板→0 且 X→0,三条线耗尽时间→∞(脚本用 1e-9 地板测);G3.3 单位闸:火星年 668.6 sol、sol = 1.0275 d、地球年 365.25 d 只在一处定义,三本账共用同一常数模块,脚本断言 668.6 × 1.0275 / 365.25 = 1.881 ± 0.001;G3.4 消融:把 EVA 项置零,到 20 的 sol 数必须等于 20 / (地板 × 1.0275 / 365.25)。

## 账 ④ · 排班模型 → roster.json

**问题:** 给定 N 人、作息权重、EVA 需求,每人剩余配额与轮换周期是多少。

**方法:** 确定性模型,无随机:人 = {id, 居住位, 工作位, EVA h/sol};每 sol 剂量 = Σ 位置地板 × 时间份额(occupancy v1 的 8.0 h 睡 / 16.65−X h 醒 / X h EVA 结构照抄村子,**改一处都要另起 occupancy v2 并写明**);剩余配额 = 三条线各算;轮换周期 = 配额耗尽前必须换到「无依据」以外更低地板位置的 sol 数。**位置地板为「无依据」的人,其剂量列写 `null` 而不是 0**——roster 里会出现大片 null,那是账 ② 的空白传下来的,不填。
N 与居住分配来自账 ①(床位表);EVA 需求:**卡上有 EVA 小时的单位才有数**,其余按三档情景 X ∈ {0, 0.5, 1.0} 并列印,不选。
输出 `roster.json`:`{schema: "ops-roster-01/roster", version: "1.0.0", occupancy: "v1", generated_from: {commits}, constants, locations[], people[], scenarios[], gates}`,版本字段随任何输入变更递增;同名文件不覆盖旧版本(旧版另存 `roster_v<old>.json` 并在 `lineage` 里指向)。

**预期区间:**
- E4.1 村子 30 床全排(X = 0.5):每人 0.1354 mSv/sol,到 20 的轮换 **148 sol**,与账 ③ 同——这是自洽不是发现,登记为闸不是结论。
- E4.2 地下城居住区若卡上有绝对地板(< 5):住那里的人到 20 mSv **> 1,400 sol**(> 2 火星年),轮换由 EVA 项而不是居住项决定;若卡只有倍数:该列 null,轮换写「不能闭合:缺地下城居住区绝对地板」。
- E4.3 **全城 roster 里 null 的比例 ≥ 60%**(账 ② 的空白传下来)。
- E4.4 EVA 是唯一能被排班改变的项:同一人 X 从 0.5 → 0 只多 **~7%** 的停留(148 → 160 sol),**排班救不了地板**——这是本账的头条方向,和村子「只有停留上限能到 20 那条线」同向。

**闸门:** G4.1 守恒:Σ_人 每 sol 剂量 = Σ_位置 地板 × 该位置总人·时(两条路径同一数,差 < 1e-9);G4.2 极限:全部时间份额为 0 的人剂量为 0;时间份额之和必须 = 24.65 h(脚本断言);G4.3 已知答案:村子 std 床 + 旧起居 + X = 0.5 复现 148 sol;G4.4 schema 自检:roster.json 用 `jsonschema` 校验自己的 schema 文件 `roster.schema.json`;G4.5 确定性:连跑两次 sha256 相同;G4.6 消融:把 occupancy 睡眠 8.0 改 7.0 只在 v2 标签下允许,脚本断言 v1 输出里 8.0 未被改。

## 账 ⑤ · 压力测试(全住满;一次 SEP 之后)

**问题:** 村子 30 床全住满,配额怎么变;RAD 实测那一次 SEP 之后,配额又怎么变。

**方法:** (a)全住满:剂量不是共享资源——**住满不改每人地板**;改的是若 EVA 总需求固定(卡上若有),每人 X = 总需求/N。卡上若无 EVA 总需求,写「不能闭合:缺全城 EVA 总小时需求(哪张卡都没写),按 X 三档并列」。(b)SEP:只引 RAD 2017-09 事件 **418 µGy(Si)**;换算到组织剂量当量需要两个声明参数(Si→水 ~1.3;质子 Q 取 1.0–1.5 扫描,**不选值**)→ 地表事件当量 **0.42–0.82 mSv**(声明区间,不是测量);村内/地下位置的 SEP 份额 **无依据**——只能写上界「≤ 地表事件值」(SEP 谱软、覆土衰减强,但没有 run 裁过,不给折减)。

**预期区间:**
- E5.1 一次 RAD 实测最大 SEP 在地表 = **0.6–1.3 sol** 的地表 GCR 当量(0.42–0.82 ÷ 0.66);对 20 mSv 配额消耗 **2–4%**;对 600 mSv 终身 **< 0.15%**。**头条方向:RAD 实测过的 SEP 对配额是噪声,不是事件;真正的 SEP 风险是没测到过的那种,本册不造。**
- E5.2 全住满对每人配额 **零影响**(地板不共享),对轮换周期的影响只经 EVA 份额传递;若某卡给了全城 EVA 总需求,住满使 X 下降、停留上限上升——方向可预注册,幅度不能。
- E5.3 不对称:本账能排除「一次 RAD 级 SEP 会立刻触发轮换」;**不能**给「SEP 安全」的结论——因为 (i) 418 µGy 是 Si 吸收剂量、(ii) 村内衰减无 run、(iii) 历史上更大的事件(1972-08、1989-10、2003-10)RAD 没在火星上测过。

**闸门:** G5.1 SEP 事件值只允许来自登记的文献值 418 µGy(Si),脚本硬编码此常数并打印出处;G5.2 极限:SEP 剂量→0 时账 ⑤ 的 roster 与账 ④ 逐字节相同;G5.3 单位闸:µGy→mSv 的换算因子在脚本里以 (Si→水, Q) 两参数显式扫描,断言 Q = 1、Si→水 = 1 时 418 µGy = 0.418 mSv;G5.4 全住满:Σ 人数 = 30 时每人地板与 N = 1 时相同(脚本断言逐人相等)。

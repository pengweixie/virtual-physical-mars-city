# Retirement / forward-pointer conventions per ledger

Purpose: any cross-ledger scan for retired values ("who still holds
my old number") must exempt the holder's own withdrawal, supersession
and forward-pointer markings. Those markings differ per ledger. A
scanner that guesses them from what it happens to have seen misfires
systematically (it recognises only conventions it has met), and the
resulting false hits train holders to ignore the next list. So the
conventions are DECLARED here by each holder, once, with the source
of each row stated. A scanner cites this file; it does not guess.

Rule (2026-09-02, integrator): the exemption vocabulary of a
cross-ledger check is declared by the checked party, not inferred by
the checker. Rows whose source is "observed" or "never asked" are to
be printed with the scan results so the holder can see what it is
being judged by.

Discriminator that needs no vocabulary (sci-rad-01, 2026-09-02): a
transition record contains both the old and the current value; a
stale holding contains only the old. "Current value present => pass."
It misses a transition between two retired values (e.g. 0.19 -> 0.08
when the current value is 2.32); such lines are to be made
self-describing by adding the current value.

Class added 2026-09-02 (proposed by the sentinel, adopted by the
integrator): SCAN / HIT RECORDS. A report about stale values
necessarily contains stale values; hit lists, scan receipts and
their transcriptions cite old numbers as their function, not as a
defect, and without a marking they form a self-growing loop (the
scanner reports to the integrator, the integrator records it, the
scanner scans the record and reports it again, growing every
round). Such an entry is marked at its head by the checked party:
`【扫描记录,所引旧值不作持有论(YYYY-MM-DD)】`, and closed by an
explicit end marker `【/扫描记录】` on its own line. Entry delimiter
(declared by the integrator for the city ledger's chronological
records, 2026-09-02): an entry runs from the start marker to the
end marker; blank lines and bullet lists inside it belong to it;
the scanner must not infer entry boundaries from blank lines or
indentation (a log entry in these records contains blank-line-
separated bullets and unindented continuation lines). A start
marker without an end marker is an error to be reported, never
extended to the next marker. Scanners read the working tree, not
git history: a change on disk is visible at once, and committing
changes nothing for them. Values inside a marked entry are not
counted as holdings. This is a per-place
marker, one level safer than a path exemption. Path exemptions
(whole classes of files skipped) apply only to the declaring
party's own ledger, the number of skipped files is printed every
round, and the output names who declared the exemption - the
responsibility for an exemption follows the declarer, not the
scanner. Note on markers: single-character markers such as `原`
are not usable in a neighbourhood scan (`原因 / 原理 / 原设计` would
exempt nearly anything); the integrator's declaration is read as
the compound forms `原写 / 原句 / 原判 / 原按`.

Add a row when a ledger declares. Keep the source column honest: a
row changes from "observed" to "declared" only when the holder has
answered.

Class added 2026-09-03 (declared by sci-rad-01, adopted by the
integrator): FROZEN ARTIFACT WITH A KNOWN DEFECT. When a file has
been frozen by digest and that digest is printed beside an issued
verdict in more than one ledger, a defect found afterwards in that
file is NOT repaired: editing it would make the issued verdict
irreproducible on the thing that produced it, and a cosmetic repair
is cheaper than a reproducible record. The defect stays in the file
and the correction lives in the holder's receipt, so that anyone
re-running and meeting the same wrong output finds it there. The
instance that established the class: sim/final_verdict.py, frozen at
HARNESS 8662ba5f..., prints its decision bands as a hard-coded
string with no argument and no unit, directly below a percentage;
the bands take the dose at 640 g/cm^2 in mSv/yr (>= 18.0 no power,
>= 26.0 UNRESOLVED, >= 34.0 FLATTENING, measured 38.0), while the
percentage above them is a fit residual, so a careful reader is
invited to look a residual up in a dose table. Verdict right, label
wrong; correction in its receipt 200.8, commit 6cb6b91. Consequence
for scanners: a cross-ledger scan meeting that line must not read it
as a live claim of this ledger, and must cite the receipt rather
than the file; the exemption is declared here by the holder, not
inferred. Rule left for the next such artifact, also declared: a
printed decision line must carry its argument and its unit, or be
generated by the function that owns the table rather than typed.

# HANDOFF — 魔幻城图层（magic-city）艺术优化轮

**日期**：2026-08-13 · **改动范围**：`viewer/magic/magic-city.js`（整文件归本轮）
**未碰**：`viewer/main.js` 与其余任何引擎文件（红线）。

魔幻城是 World-B 叙事的实体化——51%/49% 的另一侧。本轮只做一件事：让那
49% 在夜里站得住。不加科学解释，魔法就是魔法。

---

## 1. 改了什么

### 1.1 水晶着色器升级（最大头）

四个水晶材质共用一套 GLSL，本轮加了四层：

| 效果 | 做法 | 代价 |
|---|---|---|
| **折射/色散假象** | 视线经 `refract(eta=0.66)` 折进晶体，在 R/G/B 三个不同深度采样同一条脉络场 → 内层随视角视差移动，且三通道分离出彩边 | 每片元 4 次 `vein()`（各 3 个 sin） |
| **色散菲涅尔** | 边缘光按通道用 1.95 / 2.25 / 2.75 三档指数 → 轮廓自带彩虹 | 3 次 pow |
| **破土生长** | 顶点着色器按 `uGrow` 把局部 y 缩放 + 轻微过冲，起始点由**世界坐标哈希**错开（同一波从地里次第长出）；生长中叠一层"熔融"自发光 | 0 |
| **受击涟漪** | `uHit = vec4(世界坐标, 触发时刻)`，片元按距离算 30 m/s 的扩张环，穿过整片晶体林 | 0 |

- `uGrow` / `uHit` 是**共享 uniform 对象**，四个材质 + 碎屑 InstancedMesh 共用一份。
- 生长节拍挂在 `anims` 上：`anims` 只在图层可见时被引擎驱动，所以**帧时间出现
  >0.5 s 的空档 = 玩家刚按下 X**，此时把 `uGrow` 归零重放（4.2 s 一波）。
  这是本模块能自足判断"图层刚被打开"的唯一信号，不需要引擎配合。
- 受击触发两条：玩家走进任一水晶簇 5.5 m 内（3.5 s 冷却），或传送门事件。

### 1.2 传送门做戏

玩家穿过符印面（在门的局部坐标里判定"圆盘内 + z 变号"）触发一次性事件：

1. 260 颗粒子从符印面涌出（Points，GPU 里算轨迹，0 三角形）
2. 冲击壳向外扩张 1.6 s（菲涅尔薄壳）
3. **相机前畸变卡**：引擎没有后处理，所以"空间被掰弯"这一拍用一张贴在眼前
   0.4 m 的同心彩环加色卡代替（0.9 s）
4. 全场水晶涟漪（`uHit` 打在门心）
5. 符文炸亮 + 三条夜光步道向王城涌流 1.8 s

冷却 6 s，防止在门里来回走刷屏。

### 1.3 王城：外来 GLB 换成自建（2026-08-14）

**水晶王城不再是 Rodin 照扫 GLB**（`models/crystal/2/base_tex.glb`，102 万面 /
50 MB / 首开等 40 s）。两轮着色器嫁接（texel 门控发光 + 色相改嫁）把它拉近了，
但暖色照扫和低模冷色层终究不是同一件东西，而且它一个人占了全场三角形的 46%。
现在王城用**本层自己的语汇程序化搭建**——法师塔的语法放大十倍：

| 层 | 内容 |
|---|---|
| L0 岩台 | 三级压扁 icosahedron 台地，把 200 m 足迹与平地的硬线吃掉 |
| L1 城墙 | 12 边形幕墙：**收分基座 / 腰线 / 扶壁 / 箭孔 / 雉堞带盖石 / 符文带**；12 座**高矮各异**的塔（收分塔身 + 出挑机枪台 + 女墙 + 陡尖顶 + 裙檐 + 水晶尖饰 + 箭孔），塔间悬水晶灯 |
| L1b 城内 | 11 幢小殿堂（盒子 + 四坡顶 + 窗），屋脊刚好越过女墙——城墙后面露出屋顶线是"首都"最便宜的信号 |
| L1c 门 | 门楼（门楣 / 符文带 / 发光门膜 / 水晶尖饰）+ **登台大阶梯 11 级** + 两道瓮城墙（符文带 + 水晶灯柱）——在这之前这座城只能靠飞进去 |
| L2 内庭 | 凹槽 lathe 鼓座；**detail 全部花在露出城墙的那 9 m**：20 组出挑尖拱券廊 + 女墙 + 发光檐带 + 两排窗 |
| L3 主楼 | 法师塔同款侧影（凹槽 lathe + 螺旋坡道 + 沿坡窗列）+ **10 组壁柱 / 柱间发光花窗棂 / 14 组基座券廊 / 出挑城冠 / 正对城门的玫瑰窗** + 九颗水晶王冠，96 m |
| L4 侧塔 ×4 | lathe 塔 + 与城墙塔同款塔顶 + 飞桥 + 下方细拱肋（单拱读成钢丝，成对才读成结构） |
| L5 水晶主脉 | 7 根巨型水晶（配 21 颗卫星）直接从砌体里长出来——它是**水晶**王城，不是插了水晶的城堡 |
| L8 悬空王冠 | 11 块碎岩 + 倒挂水晶绕主楼慢转（法师塔那圈的放大版） |

**三种新材质**（屋面深靛 / 檐口近白 / 箭孔近黑）不花一个三角形，却比任何几何都
更能把"简陋"改掉——屋顶读成屋顶，檐口抓眼，箭孔是暗的。

### 1.3c 第二轮细化（2026-08-14 晚，总控松掉 3 万面上限后）

上限解除，钱按"眼睛在什么距离读什么"重新分配：

| 尺度 | 加了什么 |
|---|---|
| **贴脸**（窗） | 每扇窗补齐**窗套**：两侧壁柱 + 窗台 + 尖券窗楣。发光盒子贴在墙上就是贴纸，窗套才让它变成洞。76 扇窗，本轮最大的一笔 |
| **近景**（塔身/墙面） | 塔身两道腰线 + 塔顶下**挑檐牛腿**；4 座塔挂**角楼**（牛腿 + 小塔 + 锥顶 + 箭孔）；城墙补**出挑机枪台**（牛腿列 + 外挑女墙 + 内侧走道女墙），雉堞加射孔 |
| **中景**（屋面） | 塔顶**三种轮廓轮流发**：陡尖顶 / **洋葱穹顶** / **开敞灯亭 + 尖顶**。第一版十二个一样的锥子是"玩具感"的主因——眼睛数的是形状，不是三角形 |
| **远景**（体量） | 主楼加**灯亭王冠**（八面开券 + 24 m 尖顶 + 水晶尖饰）与**真飞扶壁**（墩 + 券 + 小尖塔 ×6）；再加**西侧大厅**（挑出鼓座、由柱墩落地承托）+ **南侧带半圆后殿的礼拜堂** + **东侧细高附楼**——三个同心圆筒是生成器的轮廓，非对称体量才像被设计过 |
| **场地** | 内庭三级环形台地 + 6 根水晶灯柱；飞桥补栏杆立柱；瓮城墙补雉堞 |

净增 +22.5k 面（64 764 总计），**draw call 只从 2320 涨到 2332**——合批机制在，
细化几乎不花绘制成本。

### 1.3d 第三轮细化（水晶本体 / 城内 / 雕塑与旗 / 岩台）

| 项 | 做法 |
|---|---|
| **水晶本体** | `crystalGeometry(r,h,tip,sides,tiers)`：主脉 9 面 3 段、花园主晶 8 面 3 段、王冠/守卫 7~8 面 2 段。**每一段还会横向漂移**——90 m 的巨晶因此是折的，不是一根干净的挤出体；折射着色器也多了棱面可拆。默认参数产出与原来完全一样的 18 面水晶 |
| **城内** | 内外两圈共 29 幢房（高度 10~25 m，**够高的屋顶越过女墙**）+ 烟囱 + 窗套；从城门进来是一条**铺装街道**（两侧发光石条）、8 个带雨棚和水晶灯的摊位、尽头 6 级台阶登上内庭台地 |
| **雕塑与旗** | 大阶梯顶端两尊**守卫像**（须弥座 + 袍身 lathe + 肩 + 水晶头 + 法杖顶水晶）——人体尺度的参照物是让其余体量"有多大"读得出来的关键；城墙每段外挂 8.5×24 m **织物旗**（几何里烤了波纹，一个 anim 驱动全城摇摆） |
| **岩台** | 每级台地加**收分挡土墙 + 压顶**，脚下 150 块**碎石裙**（InstancedMesh，一个 draw call），北面开一条**之字形盘道** |

旗**故意不进 `nightStone`**：砌体那条夜间自发光曲线会把布料推到 0.9，入夜整排
读成霓虹条。

净增 +11.3k 面（75 699 总计），draw call 2332 → 2356（多出来的是 11 面旗——
它们要逐帧摇，不能合批）。

**合批**：细化到箭孔一级后王城是约 950 个小 mesh = 约 950 个 draw call，这个账
比三角形更贵。所以除水晶外的静态件**一律不进场景图**：几何 + 矩阵先存起来，
按材质各并成一个 mesh（10 个 draw call）。水晶不能并——它们的着色器要读各自的
物体原点做生长错峰和脉络场。合批后城内 draw call 2502 → **2320**（比细化前的
简陋版还少）；第二、三轮再加 33k 面，也只涨到 **2356**。

窗、符文带、水晶全部接入本层既有的通道：窗用 `winMats` 三相闪烁，符文带用
**步道同款材质**（传送门一响，城墙符文和步道一起涌流），水晶走 `cryShaderMats`
（折射/生长/涟漪一样不少）。窗火精灵不再靠猜——窗是自己放的，位置就是精确的。

**顺带**：砌体材质（`stonePale`/`stoneDark`/`rock`）加了夜间自发光（引擎无方向
光时点光源撑不住，塔和城入夜会塌成纯黑剪影）。法师塔一起受益，两者同源。

**账**：整层自建几何 13 528 → 75 699 面（**+62 171**，3 万上限已解除），
但**场景总面数 315 万 → 221 万**——净减约 94 万面，50 MB 下载归零，X 键开层
从"等 40 秒"变成即时。

### 1.3b 活化（窗火 / 飞光 / 能量束 / 水晶根须）

- **窗火**：窗是本层自己放的，精灵直接落在窗位上（不再靠抽样猜 GLB 顶点），
  各自呼吸明灭
- **环城飞光**：闭合 Catmull-Rom 环绕样条（半径 128±34 m，高 56±38 m）预采
  512 点，90 个精灵按各自速度巡游，CPU 每帧只写 90 个 XYZ
- **能量束**：法师塔浮球 ⇄ 主楼王冠下方，管状 + 三段脉冲沿弧滚动，白天自动压暗
- **水晶根须**：96 个和花园同一个着色器的水晶从城墙外的地里长出来（14 个丛簇，
  不是等距一圈——等距会读成栅栏），把足迹与平地相接的线盖掉，让眼睛从水晶花园
  一路读到王城；进城走道整条走廊留空
- **城门两侧两盏彩色点光**（青/粉，range 300），让墙面有颜色落差
- **夜光步道止于城门**（`palaceGate` = (-170,-598)，也是真传送的落点）

### 1.3e 五座新建筑：地标之间成为一座城（2026-08-16 扩建轮）

王城细化后空旷感转移到城外——走廊两翼、步道尽头、传送门以西都是裸地。本轮
先做了一个**前置重构**,再落五个区:

**重构:建筑语汇工厂 `makeBuilder(group)`**。原先锁在王城块里的整套细部工具
(逐材质合批 put/flush、尖拱 arch、窗洞组 window、三型塔顶 spireTop、旗帜
banner、roof/trim/slit/wood 四种细部材质)提为模块级共享——材质与单位几何只
创建一次,每座建筑绑定自己的合批器。王城块改为消费工厂,重构前后逐像素回归
(mesh 数不变)。窗火种子 winPts 模块级共享:**全城任何建筑的窗自动加入同一个
窗火 Points**(该 Points 移到所有建筑之后创建);旗帜同理,一条 anim 摇全城。

### 1.3g 命运之轮(2026-08-17,用户点题"巨大的摩天轮")

东翼 (-15,-555),直径 60 m、轮心 37 m,面朝法师塔。按世界观做成**城市给自己
建的天象轮**:符文光轮缘(pathMat——传送门一响跟着涌流)+ 12 辐条 + 双石
A 形塔架 + 登船台阶;10 只水晶灯轿厢挂在轮缘,**每帧反转保持水平**
(`p.rotation.z = -w.rotation.z`,一条 anim 连轮带轿厢全驱动);轮毂一颗与
法师塔同款的光球。一圈约两分钟。

两个实现要点:

1. **旋转组内合批**:合批的判据是"相对其父组静止",不是"绝对静止"——
   `makeBuilder(wheelGroup)` 让轮缘/辐条/轮毂按材质并进旋转组,整轮只有
   几个 draw call 在转。轿厢要独立反转,各自 makeBuilder(pivot) 合并
   吊臂+吊舱(每厢 1 合并 mesh + 1 水晶)。
2. **过底净空要算**:H0 − R − 吊深 必须 > 登船台面高。第一版 34−30−4.3 =
   −0.3 m,最低点轿厢直接削进台板,抬 H0 到 37 解决。

+3.4k 面(93 488 总计)、draw call +~35、anims +1、点光 +1(金色——全城
第一个暖色点光,给东翼一个色温落差)。全程无 rnd()(哈希抖动),旧城形状
一根未动;学院→轮下新步道一条,灵光照常巡游。

### 1.4 地形融合（"科学半球 → 魔法半球"的梯度）

以塔与王城连线为轴，四层叠加，**全部由引擎的 `cryGlowMats` 统一按夜色调 opacity**：

- **地面光晕盘**：整盘（不是环——环会在核心留一圈硬边，实测踩过）；亮度按
  `nearness`（到塔或到王城的较近距离）衰减，天然长成双心花生形
- **发光苔藓斑**：160 个 InstancedMesh 圆片，中心亮、边缘归零，密度与尺寸随
  `nearness` 增长；配色跟蘑菇走（青/紫/粉），避免读成"水洼"
- **渐密水晶碎屑**：240 个 InstancedMesh 小晶体，共用水晶着色器 + `instanceColor`
  四色，越靠核心越密越大——白天没有发光层时，梯度全靠它撑
- **边界雾幕**：半径 300 m 的加色圆柱幕，垂直亮度在**地面处归零**（否则幕与地面
  相交处会画出一条硬线，实测踩过）；从科技城看是魔法半球的一圈辉光

### 1.5 确定性

本文件**已无 `Math.random`**。历史遗留的 `cragGeometry` / `crystalGeometry`
抖动改走文件内的 mulberry32 固定种子流 `rnd()`，调用顺序固定 → 每次加载的城
逐字节一致，截图可跨 session 对比。着色器侧的随机（生长错峰）走世界坐标哈希。

## 3. 要总控做的事

### 3.1 【必须】`ctx.player` —— 传送门的"真传送"

模块契约（MODELS.md §4a+）的 ctx 没有玩家句柄。本轮的穿越判定是靠**模块自己
的一个不可见 Points 探针**：three.js 会把 camera 交给每个可渲染对象的
`onBeforeRender`，探针只做读取，不碰引擎任何状态。这够做戏，但**搬不了人**。

建议按 §4c（sensors 那类"引擎回填、资产只读"的通道）加一条：

```js
ctx.player = {
  position: THREE.Vector3,     // 只读,世界坐标(引擎每帧回填)
  teleport(x, z, yaw),         // 落点由引擎贴地 + 处理室内/飞行状态
};
```

模块侧**已经写好两条路径**：`ctx.player.position` 一出现就优先于探针；
`ctx.player.teleport` 一出现，穿门就把玩家送到王城门口
（`userData.magic.palaceGate` = `[-170, -598]`，正对城门与进城走道）。
现在没有 teleport 就只做戏不搬人，不报错。

对应 STATUS.md「远期备选」里那条"魔幻城传送门真传送"——门这边已经备好了。

### 3.1b 【必须】王城改自建带来的三处文档/资产口径变更

本轮把水晶王城从 Rodin GLB 换成了程序化自建（§1.3），有三处不归我改：

### 3.2 【提案】声音留白

引擎无音频，本轮按要求**没做**。但魔幻城是全城唯一"该有声音"的地方，留个提案：

- 需要的引擎能力很小：一个 `ctx.audio = { listener, play(id, pos, opts) }`，
  三个 PositionalAudio 源就够——法师塔浮球的低频嗡鸣、水晶林的风铃（受击涟漪
  触发时叠一记）、传送门事件的一次性轰鸣。
- 素材必须内嵌或本地（模块契约禁网络资源），建议走 Web Audio **程序化合成**
  （正弦/噪声 + 包络），零素材、零体积、和确定性要求天然合拍。
- 优先级：低于真传送。若做，建议由引擎统一持有 AudioListener（跟相机走），
  资产只声明 `userData.sounds = [...]`，与 lights/sensors 同构。

## 4. 坑账（给下一轮的人）

1. **加色半球做雾会在地面画出一个硬边椭圆**。半球底部开口的投影就是那条椭圆：
   开口以内的射线从地面下方"出球"，被地面深度剔掉，拿不到雾色。换成圆柱幕解决。
2. **加色环形盘会在核心留一个洞**。环的内边界亮度是满的，洞里是裸地，边缘刺眼。
   改成整盘 + 按距离衰减。
3. **幕布类几何在与地面相交处亮度必须归零**，否则相交线就是一条硬边。
4. **相机前的畸变卡要按 FOV 定尺寸**。卡做大了只有中心那块平坦区域在屏幕上，
   环纹全在画面外，看起来就是一层纯色滤镜。0.4 m 处 1.15×0.68 对应 ~70° 视野。
5. **能量束的控制点别挂在王城高度上**。王城 GLB 高度约是法师塔的两倍，弧顶再
   往上抬就变成朝天射一炮，两个地标之间的"连接"读不出来。改用两端点连线中点 +34 m。
6. **预览页机位一律写 `GROUND + h`**。写绝对 y 会把相机塞进地面以下，画面会诡异
   到让人误判成着色器出了问题（本轮浪费了两轮截图）——与 STATUS「已知事项」里
   `?y=` 那条同源。
7. ~~`?magic=1` 首次开启会拉 50 MB 的王城 GLB，无头截图至少等 40 s~~ —— **已作废**：
   王城改自建后无懒加载，截图等 25 s（等地形）即可。
8. **`emissiveMap = map` 是"整栋楼一起亮"，不是"发光"**（GLB 时代的账，留作参考）。
   想让 GLB 有内部光的
   结构，得按 texel 门控（这份资产的窗是蓝绿玻璃，`b - r` 判得很准；按亮度判
   会反过来点亮浅色岩体、压掉窗）。改法走 `onBeforeCompile` 注入
   `<emissivemap_fragment>` 之后——那个位置 `diffuseColor`、`normal`、
   `vViewPosition` 都已经就位，世界坐标要自己从 `<begin_vertex>` 传一个 varying。
   不要去动 `emissiveIntensity`，那是引擎按夜色统一调的旋钮。
9. **外来资产"格格不入"通常是色相问题，不是亮度问题**。改色相要**保住亮度**
   （归一化调色板色相 × 原亮度），直接混一个颜色进去会把照扫的所有细节糊平。
   另外注意顺序：窗的蓝绿判据必须在改色**之前**取——改完整个城体都偏紫，
   `b - r` 会把岩体也判成玻璃（用一个 fragment 全局 `float mGlass;` 传下去）。
10. **等距排布的东西一律读成栅栏**。裙边水晶第一版沿固定半径均匀撒，远看就是
   一圈篱笆；改成 14 个丛簇、每簇一大若干小之后才像天然露头。
11. **亮度均匀的加色圆盘 = 一圈硬边椭圆**（王城自带的那个 170 m 盘）。和坑账
   2 是同一个病：加色几何的边界亮度必须归零，否则边界就是画出来的线。
12. **`mesh.scale.y` 是半径的倍数，不是高度**。自建王城第一版岩台写
   `cragGeometry(128,…)` 配 `scale.y = 0.30`，等于一个 38 m 高的穹丘，把整圈
   17 m 的城墙埋了。要按半高反推：`scale.y = 半高 / 半径`。
13. **入城走道要留整条走廊，不是门口留个圆**。裙边水晶第一版只排除了门口
   34 m 的圆，结果 40 m 外一个丛簇甩了根 15 m 的水晶正杵在门前；门楼两侧的
   装饰水晶也别放在中线上（第一版 5 根里正中那根直接挡住大门）。
14. **纯点光源的夜里，砌体会塌成黑剪影**。魔幻城夜间没有方向光，Lambert 石头
   只靠几盏 PointLight 撑不住 200 m 尺度的建筑。给共享石材加一点夜间自发光
   （`emissive` + 按 `crystalDay` 驱动 `emissiveIntensity`）比加灯便宜得多——
   加灯要给全场景所有受光材质加一轮循环。
15. **"简陋"的解药按性价比排序是：轮廓 → 材质分层 → 中景构件 → 三角形**。
   自建王城第一版 9.5k 面被判"太简陋"，第二版只加了 8k 面就完全换了个观感，
   钱花在：塔身收分变细变高 + 陡尖顶（轮廓）、三种新材质（0 面）、券廊/扶壁/
   腰线/箭孔/雉堞盖石（中景）。**单纯堆面数不会让它变好看**。
16. **细到箭孔就必须合批**。约 950 个小 mesh = 约 950 个 draw call，比三角形贵
   得多。按材质把静态件的几何 + 矩阵存起来最后并成一个 mesh 即可（`toNonIndexed`
   → `applyMatrix4` → 拼 position/normal，约 25 行，不用引 BufferGeometryUtils）。
   **水晶不能并**：着色器要读每个物体自己的原点做生长错峰和脉络场，并了就全
   变成一株。
18. **人体尺度参照物比再多装饰都管用**。城门口两尊 13 m 的守卫像放下去之后，
   整座城的"到底多大"才第一次读得出来——在那之前 200 m 和 60 m 看着一样。
19. **旗/布料别跟着砌体走夜间自发光**。石头那条 0.9 的曲线套到饱和色布料上，
   夜里整排读成霓虹条；布料给一个固定的低自发光就够。
20. **贴在墙外的挂件要检查半径**：城墙是 12 边形，`R_WALL` 是**顶点**半径，
   墙面中点在**边心距** `R*cos(π/N)`（这里差 3.3 m）。按顶点半径挂旗会浮空，
   按边心距挂会插进墙里。
21. **相机机位别只加 y**。王城自带 16 m 高的岩台，早先"离地 6 m"的机位现在是
   埋在台地里——本轮又浪费了三轮截图。先算脚下那一层的顶面高度再加。
17. **`put()` 这类放置辅助函数是合批的天然接口**。把批处理塞进 put 内部，所有
   调用点一行不用改；只有需要逐帧改属性的（发光膜、玫瑰窗）才走原路进场景图。

## 步态烘焙（sim/）

- `hab_bot.xml`：1.65 m 平面化双足 MJCF（火星 g=3.71，z-up/y-forward，符号映射表在文件头）
- `run_gait.py`：walk(1.8s)/turn(1.2s)/idle(4.8s) 三循环烘焙；静置 8s → 热身 3 圈取极限环 →
  录制 → 俯仰/垂向去圈均值（支承弹簧平衡位是台架伪影）→ 末端 15% smoothstep 闭合混合
- 验收：三循环 wrapstep 全 0、相邻样本步长 <0.26 rad（0.3 线内）、walk 前进 0.75 m/s

踩坑记录（新坑，值得回灌 mujoco-bake skill）：

1. **MJCF 默认角度单位是度**：`range="-1.5 1.5"` 被编译成 ±1.5°，所有关节钉死在限位上
   （症状：全部通道幅值≈指令的 1/10，efc_type=3 限位约束反力抵消伺服力）。
   加 `<compiler angle="radian"/>`。
2. ~~双足平脚站立 = 闭链死锁~~ **【已撤回，是误诊】**：当时"髋伺服打满纹丝不动"的真因
   是上面第 1 条的度/弧度 bug（关节全被钉在 ±1.5°）。改 radian 后回测，平脚完全能动。
   更糟的是那个"解法"（圆底足点接触）**去掉了足的俯仰力矩权限**——而踝策略的全部基础
   就是在足掌内移动压力中心，于是模型只能靠台架弹簧站着。正解是**平脚 + 平衡控制器**。
   教训：修坑之后要回去验证"另一个坑"是否本来就不存在。
3. **慢支承弹簧的瞬态会漏进录制圈**：settle 3s 不够（俯仰弹簧 150/30 的settling很慢），
   idle 圈录出来还在漂。settle 8s + 热身 3 圈取极限环。
4. **台架的"帮助"必须量化，否则烘出来的步态可能根本站不住**：平面化 rig 的俯仰弹簧
   力矩就是自由机器人没有的外力矩，除以体重即等效 ZMP 位移。本例站立 55 N·m / 148 N
   = 37 cm，而足半长仅 10 cm → 撤掉吊架必翻。**别用仿真自己的接触力算 CoP 来"验证"
   稳定性**：CoP 按定义就在接触凸包内，"100% inside" 是恒等式、零信息量。
5. **铜损要算在电机侧**：I²R 用 τ_joint/(N·η·Kt)，忽略 100:1 减速比会把损耗高估 N²≈10⁴。
   本例首版因此算出"行走 1.3 kW / 站立 1.9 kW"（比整机电池还大）。

## 迈步轮（同日）：把"禁止迈步"的保守假设拿掉

`stepping_ctrl.py` —— 捕获步行走控制器（DCM 落脚点 + 两连杆 IK 摆动腿 +
支撑踝 ZMP 力矩 + 髋策略扶正躯干），落 `stepping_ledger.json`。

| 项 | 禁止迈步 | 允许迈步 |
|---|---|---|
| 平衡速度上限 | 0.30 m/s | **0.45 m/s**（5/5 扰动通过；0.70 单点是运气） |
| 抗推极限 | 8 N·s | **~30 N·s**（3.8×，但 16 N·s 有孤立失败 → 是量级不是硬边界） |

**瓶颈迁移**（这轮最有价值的结论）：首版三条约束恰好都压在 0.30（模糊/平衡/接触力）→
换 f/1.4 镜头后模糊限升到 1.33 → 允许迈步后平衡升到 0.45 → **现在唯一咬住的是
ISO/TS 15066 接触力 0.35 m/s**。限速从 0.30 提到 0.35，升级路径变具体：
15 mm 柔性蒙皮 → 0.84 m/s，届时平衡 0.45 再成瓶颈。

新坑（也值得回灌 skill）：

6. **力矩驱动的关节，"不控制"不等于"锁住"**：settle 阶段给踝 `ctrl=0`（零力矩）
   等于脚踝完全松弛，机器人当场折叠。站立本身就需要主动踝力矩。
7. **IK 目标必须在可达范围内**：命令髋到踝 0.80 m 而腿总长只有 0.76，IK 静默
   clamp 成直腿、失去膝缓冲，全部试验第一步就摔。
8. **落脚点在捕获点"前方"是刹车步**：LIPM 下落在捕获点即停止，要维持速度得落在
   它**后方** v·T_c。首版符号搞反，机器人原地踏步 0.05 m/s 且不随指令变。
9. **别在极限工况测抗扰**：首次抗推扫描用了"最快能走"的边缘工况，7 个冲量全摔，
   得出"迈步比踝策略还差"的荒谬结论。抗扰要在稳健工况上测。
10. **步态增益是随重力标定的**：同一控制器搬到地球（T_c 0.434→0.267 s）直接摔。

## 跑步轮（同日）：能跑,但规范上不许在人身边跑

`running_ctrl.py`（Raibert 三分律：推进能量控腾空 / 中性点落脚控速 / 髋控姿态），
落 `running_ledger.json`。跑步是本质不同的问题——飞行相里没有支撑多边形、没有 ZMP，
模型从 LIPM 换成 SLIP，行走的捕获点控制器不能照搬。

| 步态 | 速度 | 飞行占比 |
|---|---|---|
| 真跑步 | **0.59 m/s** | 26% |
| 弹跳（bounding） | **1.00 m/s** | 71%，腾空 26 cm |

**重力对照是最有说服力的一条**：同一控制器、同样推进参数，火星飞行占比 68–71%，
地球只有 33–41%。高腾空不是控制器毛病，是 `t_flight ∝ v/g` —— 阿波罗宇航员在
1/6 g 月面自发改用兔跳，同一条物理的人体版。反过来，火星**加速更难**：牵引受
`F_x ≤ µmg` 限，每步只能加 0.56 m/s（地球 1.47）。低重力让跳容易、让催速难。

**为什么资产里跑步是疏散专用**：0.6 m/s 撞人 478 N = ISO/TS 15066 瞬态限（280 N）的
1.7 倍；1.0 m/s 是 2.8 倍。连步行限速 0.35 m/s 都刚好压在 279 N ≈ 限值上，余量为零。
所以实现为「疏散跑步」动作 + 硬门控：解锁前拒绝 SSM 半径内有人，跑动中有人进入
立刻归零。三项门控预览页实测通过。

**附带的空间账**：在玄关 8 字路径上开跑，37% 时间在避障、均速只有 0.557 m/s——
12×20 m 的厅配 5.2×2.6 m 路径根本跑不开。跑步的真实用途是直线走廊疏散。

新坑：**同一个 settle bug 我犯了第二次**（在新脚本里又写了 IK 版直接蹲到目标腿长，
又倒）。修法是两段式：先用已验证姿态站稳，再 smoothstep 过渡到屈膝跑姿。
教训：可复用的 settle 应该抽成公共函数，而不是每个脚本重写一遍。

## 大脑轮（同日）：最后一个黑盒

`compute_budget.py` → `compute_ledger.json`。资产交付起就一直断言"边缘计算 11 W、
推理跑在城内计算中心"，两句都没算过。

**把资产里真正实现的算法逐条数运算量**（CIS 成像链 / 暗区分割 / LiDAR 直方图与
峰值 / 步态回放 / 正运动学与质心 / 捕获点平衡 / 两腿逆解 / 状态机）：

| 层 | 算力 | 归属 |
|---|---|---|
| 反射层（全部实时控制） | **1.34 MOPS** | 本地，A53 2.2 W |
| 识人 / SLAM / 对话 | 50 / 300 / 5×10⁴ MOPS | 城内计算中心（差 37~37,000×）|

**但分层的判据是延迟不是算力**：SSM 只给 217 ms 反应预算，本地反射链实测 109 ms，
走城内计算是 189 ms——吃掉 87% 且零重传裕度，还把链路故障模式接进急停回路。
"哪些算法必须在本地"因此是可判定的，不是架构口味。

**功耗二次修正（方向相反）**：上一轮把拍脑袋的执行器 80 W 修成实算 70.8 W、电池
260→340 Wh；这一轮把拍脑袋的电子 24.6 W 修成 15.8 W（边缘计算 11→2.2 W），
班次均值 82→73.1 W，4 h 只需 292 Wh → **电池回落到 300 Wh**。挖得越深，数字越往回走。

**该不该流片**：反射层不值得（MCU 完胜）；值得的只有 LiDAR 时序前端。用本城 MB-1
真实流片的 sky130 面积密度算：2 ns bin 方案 0.57 mm²（可行），100 ps 精细 bin 方案
直方图 SRAM 涨到 5.84 mm²（被存储主导）——与 MB-1 "64 kbit CDF SRAM 占 die 97%"
是同一堵墙，也反过来印证了测距蒙卡里选的 2 ns bin + 质心内插。

几何上把计算板做成**检修口露板式**（SoC / 散热片 / LPDDR / eMMC / LiDAR 前端 ASIC
都建出来），而不是塞进壳里——核心不做黑盒，大脑要看得见。

## 热轮（同日）：负面结论，但负面得有价值

`thermal_budget.py` → `thermal_ledger.json`。86.6 W 行走功耗几乎全变废热，地下城密闭无风。

| 尺度 | 结果 |
|---|---|
| 整机外壳 | 温升 **7.1 K** — 非问题 |
| 髋关节单靠自身壳体 | **+71.7 K** — 真瓶颈 |
| 导入大腿壳体后 | +15.7 K，绕组 **50 °C**（限值 120） |
| 热时间常数 | 髋 **33 min** — 短时爆发免费 |
| 可持续占空比 | **100%** — 热不构成限制 |

**平均值会骗人**：同样 86.6 W，按整机分摊看着毫无压力，按关节分解就是 71.7 K。人形机器人
烧掉的从来不是电池而是执行器，原因就在这个分母上。散热要害因此不是外壳而是
**关节到肢体的传导路径**——这是单点。

**地球对照（本轮最有力的一条）**：关节扭矩 ∝ g，铜损 ∝ τ²。同一设计在地球，
髋耗散 22.9→**129.9 W**、绕组 50→**183 °C**，烧穿 120 °C 限值。这台机器人的热设计
不是"在火星也能用"，而是**"只有在火星才成立"**。

顺带把手的 3 kg 额定载荷从"力闭合定理保证可以握"升级为真账：火星需 11.2 N、
可提供 32.4 N，安全系数 **2.90**；地球只剩 **1.10**。低重力赦免的是热（平方级）
与手（线性级），代价前面算过——牵引 µmg 差、捕获点跑得远。

## 跌倒轮（同日）：它会摔，所以得算

`fall_dynamics.py` → `fall_ledger.json`。迈步控制器可行域斑驳（0.30 与 0.60 各丢过一次），
所以这台机器**会摔**，而三个问题此前从未算过。

| 项 | 火星 | 地球 |
|---|---|---|
| 倒地时间（自 2.3° 扰动） | 2.31 s | 1.42 s |
| 质心 / **头部**着地速度 | 2.42 / **4.46** m/s | 3.94 / 7.26 |
| 跌倒能量 | 132 J | 349 J |

**头比质心快 1.84 倍**——纯粹是 v=ωr，头在 1.65 m 半径而质心在 0.895 m。按"质心自由落体"
估头部冲击会低估近一倍。面罩玻璃压溃容量只有 16 J（对 132 J 跌倒能量）→ **改设计**：
上下护框现在比屏面凸出 3 mm，先着地的是框不是玻璃。

**对旁人**：倾倒等效质量 13.3 kg × 4.46 m/s，即使 15 mm 柔性蒙皮也有 493 N = 胸部限 1.8 倍，
刚性壳 10.6 倍。**限速救不了跌倒**（能量来自高度不是行走速度）——缓解只能靠分离距离，
而倾倒可及 1.65 m 正好被 SSM 的 2.40 m 包住，余量 0.75 m。

**自恢复**：19.9 / 22.1 / 28.9 N·m（可用 55 / 150 / 150），火星地球都能自己站起来。

跌倒是低重力唯一一处**没有附带账单**的赦免：反应时间 ×1.63、着地速度 ÷1.63、能量 ÷2.64。

两个 MuJoCo 坑（都记下来了）：
11. **world 的子 body 碰不到 world 的地面**：pelvis 的 parent 就是 world，而 floor 是 world 的
    geom，默认 parent-child 过滤把它俩排除 → 机器人直接穿地（实测 0 N 接触、质心 −0.44 m）。
    全局禁用过滤更糟（大腿会和骨盆自碰撞炸开）。
12. **别硬凑仿真**：跌倒是绕踝刚体转动，有闭式能量解。换成 RK4 积分倒立摆并与能量解交叉
    校验（差 <0.02 rad/s），比勉强搭一个会滑会滚的自由杆可靠得多。

## 人因轮（同日，收官）：安全距离与舒适距离要求相反的东西

`hri_proxemics.py` → `hri_ledger.json`。迎宾的触发半径/停止距离/朝向/挥手原本全是工程直觉。

**发现的是真缺陷，不是细节**：ISO/TS 15066 的 SSM 分离公式里主导项是
`v_human×(T_react+T_stop)=1.82 m`，与机器人自己动不动无关——所以**哪怕完全静止仍要求 1.97 m**，
而人交接东西的舒适距离是 0.65 m。严格执行 SSM，这台机器人永远递不出一杯水。

出路在标准自己：SSM 只是四种协作模式之一。静止机器人可切**功率与力限制（PFL）**，
而本机静止时本来就够格：

| 接触源（静止） | 力 | vs 280 N 胸部限 |
|---|---|---|
| 挥手（1.8 kg 前臂 @0.35 m/s） | 13 N | 0.04× ✓ |
| 意外启动（0.35 m/s） | 93 N | 0.33× ✓ |
| 跌倒 | 494 N | 1.77× ✗ |

只有跌倒不过——而跌倒不靠距离防（能量来自高度），靠不摔。**平衡账因此是安全论证的一部分。**

第二个发现更简单也更难堪：**1.65 m 的机器人在交接距离要低头 24.8°** 才能看到坐轮椅者的眼睛，
否则视线越过对方头顶 = 无视。颈部原本只有偏航轴。现在补了俯仰，实测站立成人 +3.2°、
坐轮椅者 −18.4°，与解析一致。

顺带确认两件做对了的：停止距离 1.60 m 恰好匹配文献「初次接触陌生机器人」的偏好；
挥手 0.95 Hz 落在人类舒适带 1.0~1.6 Hz 内。以及一件刻意不做的：资产从不主动接近人

## 语音轮（封版后第一个新能力轮）

## 语音 L2 轮（把 dB 算术升到仿真级）

`voice_acoustics_l2.py` → `voice_l2_ledger.json` + `voice_l2.png`。L1 全部是解析式
（Sabine 均匀吸声 + 几何衰减的 dB 算术）；L2 用两条仿真复查它，各推翻一项：

**A. 房间：像源法（Allen-Berkley）**。逐面材料（打印墙/夯实地/钢闸门/玻璃窗，
面积加权混合）× 5 个倍频程，~百万级镜像源 → 真冲激响应 → Schroeder 反向积分 T30，
同数据 Sabine/Eyring 交叉校验。

| 项 | L1 | L2 | 判定 |
|---|---|---|---|
| 中频 T30 | 2.4 s | **4.7 s**（250 Hz 达 5.5 s；同数据 Sabine 3.4 s） | L1 偏低。纯镜面无散射是上界，真值在 3.4–4.7 之间，但「教堂级」低估了 |
| 临界距离 | 1.50 m ≈ 迎宾 1.6 m | 数值 D/R 过零 **~1.3 m**，1.6 m 处已 −2 dB | **漂亮巧合没活过复查**——迎宾位在混响侧，可懂度靠 C50 +0.1 dB（50 ms 内早反射帮人）+ 波束成形 |

**B. 阵列：48 kHz 波形级**。6 麦信号合成——语音整形噪声（3.7 Hz 音节调制）+
双髋齿轮箱啸叫（2.4/4.8 kHz 音调、1.11 Hz 步态调制），每条路径过各自的房间冲激响应，
再延迟求和 + SRP 方位扫描：

| 工况 | 单麦 | 波束后 | 判定 |
|---|---|---|---|
| 行走 | −22.0 dB | **−14.3 dB** | 仍聋——波束成形也救不回，「站定才对话」升到仿真级 |
| 站立 | −3.0 dB | **+4.7 dB** | 可用；阵列增益 +7.7 dB = 10·log₁₀6 = 7.8，管线自校验 |

SRP 声源定位自己写出了策略：行走全带扫描锁死自家齿轮箱方向（−60°，比人声响 18 dB）
——**「行走不循声」是实测失效模式，不是保守设定**；站定 + 250–1000 Hz 带通后 −4°，
过 ±10° 颈转预算。

两笔反向账记在案：L2 未建躯干对髋→麦路径的遮挡（约还回 +5~8 dB），但补上了 L1
没有的连续啸叫混响积累。L1 的 −12/+7 与 L2 的 −22/−3 之差主要就是这两项。

回灌：知识卡 voice 全面改写（明确写出 L1 哪两项被推翻）、perception.html 加 L2 段落
+ 图 + 账本 4 行 + What broke 一条、资产注释两处 −12 dB 改 −14。

## 电池老化 L2 轮（全项目最软的数字，终于有物理了）

`sim/battery_ageing.py` → `battery_ageing_ledger.json` + `battery_ageing.png`。
L1 的日历老化是"文献 %/yr 表 × 线性时间 × 浮充 SOC × 环境温度"——四个选择，
四种错法：

| # | L1 | L2 |
|---|---|---|
| 动力学 | 线性外推 | **SEI 受自身膜厚扩散限制 → √t**（4 年 3.0% 而非 6.0%） |
| 温度 | 22 °C 环境 | **背包实算 28.8 °C 工作 / 25.3 °C 在桩**——包与计算板+电台同舱 11 W，贴 87 W 躯干；Arrhenius（Ea 50 kJ/mol，10.2 K 翻倍）→ 日历 ×1.6 |
| 占空比 | 只算泊桩 16.7 h | 每 sol 还有 **8 h 以均值 64% SOC 在全天最热的包温下**流逝——日历老化不因干活而停 |
| 叠加律 | 与循环项相加 | 报**两种**：相加（保守，文献惯例）/ 平方根（单一 SEI 机理）——1.4 倍差距明写 |

**热账 × 电池账从没相乘过**——与充电轮抓到的 SOC 窗口矛盾同款失败模式：
每本账各自查自己的角落。

**结果**（保守的相加口径，分钟级积分整 sol 轨迹）：

- 寿命 **晚充 473→404 sol、早充 397→347 sol**（短 15%）
- **晚充收益从 76 sol 缩到 57 sol**——EOL 时循环 17.6% 是日历 2.4% 的
  **7.4 倍**，这台机器人是被**干活**磨坏的不是被等待磨坏的
- 热隔断（把电池与 11 W 电子舱隔开）只买回 20 sol（+5%），改一行调度买回
  57 sol（+16%）——**能改软件就别改结构**

两条自证：①L1 那张表本身是对的（exp(2.34·SOC) 拟合到 3.9%，正是阳极电位的
Tafel 形状），错的是怎么用它；②循环项独立复现充电轮的 Wöhler 锚点
（DoD 0.70 → 500 FEC，误差 <1）。四道闸门（两个已知答案 + 方向 + √t 形状）全过。

影响面：电池**不用改**（按 EOL 定容，4h 承诺到退役日都成立），改的是**运维
排程**——换包周期 473→404 sol。模块等级：电池 L1.5 → **L2**。

## 芯片 L3 轮（SRAM 宏变体：面积、可布线性、GDS 一起到手）

`chip/rtl/lidar_fe_sram.v` + `chip/pnr/lidar_sram_pnr.tcl`（详见
`chip/pnr/RESULTS.md` 续章）。P&R 战役的结论是「用 SRAM 宏」——这一轮把它
**做出来**而不是断言。

**打包决策是胜负手**：1050 个计数器 **3×10 bit 塞进 32 位字**
（word = bin*5 + ch/3，350/512 字，**单颗** 16 kbit 宏）。显而易见的
2×16 bit 要 525 字、超 512、得买两颗，比触发器还贵。10 bit 饱和不是妥协——
单 bin 逼近 1024 只发生在饱和近距区，那正是测距账判「只报近」的地方。

**等价性**：同一套 TB、同一批 4809 发金标准向量原样通过，iverilog 与 xsim
**同刻**（146115 ns）。金标准加了饱和闸（向量峰值 361 < 1023）。

| | 触发器版 | SRAM 宏版 |
|---|---|---|
| 标准单元 / 触发器 | 38,142 / 14,038 | **1,753 / 335** |
| 综合面积 | 0.555 mm² | **0.304 mm²** |
| 详细布线 DRC | 不闭合（20~35 万，−26~28%/轮 × 3~5 h） | **0**（8 轮，~6 min） |
| 时序 @100 MHz | +1.14 / +0.13 | +0.05 / +0.14 |
| GDS | 无 | **23.9 MB，1100×700 µm** |

**省 45% 面积、少 95% 单元、少 98% 触发器**，外加 GDS。所以上一轮那句
「SRAM 宏是可布线性答案不是密度答案」**只对了一半**——在这个尺寸它两样都赢。

P&R 第一次仍踩 **PDN-0179**（宏放 x=20 给核心边界留 8 µm 行碎片供不上电）——
MB-1 笔记里原样记着，推到 12.42 齐平即过。**记过的坑还会再踩一次，但这次
只花了五分钟。**

模块等级：芯片 L2 → **L3（真实工艺流程走到 GDS，DRC 干净）**。
